# Verification backlog

Claims this repository makes that **no test in it can check**, each with the
experiment that would settle it. Created at M3, when the first code that draws
something landed and the gap between "the suite is green" and "it works on a
phone" became real.

**The rule, and it is the whole point of the file: an entry with no concrete
procedure is not an entry.** Same discipline as `tool/dep-allowlist.txt`, and
for the same reason — "verify on device" is a promise, not a plan, and a
promise is what this file exists instead of.

**"Cannot be checked headlessly" is a MEASURED conclusion here, never an
assumption.** Where the measurement exists it is cited. Where a claim turned out
to be checkable after all, it is not in this file: the nested-category contract,
the poster route's 200 branch, the manifest merge and the plist parse were all
assumed device-only in the M3 plan and all turned out to be measurable, which is
why they are tests and builds rather than rows.

Rows are retired by doing them, and a retired row keeps its result rather than
disappearing.
